# الشعلة لخدمة السيارات — نظام التشغيل اليومي

تطبيق ويب حقيقي (وليس نموذج تجريبي) لمحطة الشعلة لخدمة السيارات — كلباء. مبني بـ **Next.js 16** (Server Actions،
بدون REST API منفصل) و**Supabase (Postgres)** كقاعدة بيانات حقيقية، وينشر مجاناً على **Vercel**.

كل أسعار الخدمات ونسب عمولة البنك وقائمة الموظفين **بيانات في قاعدة البيانات** يمكن تعديلها من شاشة `/admin`
بدون لمس الكود، وكل تعديل نسخّي (versioned) — العمليات القديمة تحتفظ بالسعر/النسبة التي كانت سارية وقتها.

---

## 1) إنشاء قاعدة بيانات Supabase (5 دقائق، مجاني)

1. افتح [supabase.com](https://supabase.com) وسجّل دخول (يمكن بحساب GitHub).
2. **New Project** → اختر اسم (مثلاً `alshulah-cars`) وكلمة مرور لقاعدة البيانات (احفظها بمكان آمن) والمنطقة الأقرب.
3. بعد إنشاء المشروع، اذهب لـ **SQL Editor** من القائمة الجانبية.
4. افتح ملف [`supabase/migrations/0001_init.sql`](./supabase/migrations/0001_init.sql) من هذا المستودع، انسخ محتواه بالكامل، الصقه بمحرر SQL، واضغط **Run**.
5. كرّر نفس الخطوة لملف [`supabase/migrations/0002_seed.sql`](./supabase/migrations/0002_seed.sql) (يعبّئ الأسعار والموظفين الابتدائيين المطابقين لقائمة الأسعار الحالية).
6. اذهب لـ **Settings → API** واحفظ قيمتين:
   - **Project URL** (مثال: `https://xxxxxxxxxxxx.supabase.co`)
   - **service_role secret** (تحت API keys — وليس `anon` key؛ هذا المفتاح سري ولا يُستخدم إلا بالخادم)

---

## 2) إعداد المتغيرات محلياً (اختياري — للتجربة قبل النشر)

```bash
cp .env.example .env
```

عبّئ بملف `.env`:

| المتغير | القيمة |
|---|---|
| `SUPABASE_URL` | رابط المشروع من الخطوة السابقة |
| `SUPABASE_SERVICE_ROLE_KEY` | مفتاح service_role من الخطوة السابقة |
| `APP_PASSWORD` | كلمة المرور التي ستدخل بها للتطبيق (اختر كلمة قوية) |
| `SESSION_SECRET` | سر عشوائي طويل — ولّده بالأمر: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |

ثم:

```bash
npm install
npm run dev
```

افتح `http://localhost:3000` وسجّل الدخول بكلمة المرور التي اخترتها.

---

## 3) النشر على Vercel (مجاني، دومين ثابت)

1. ادفع هذا المستودع لحساب GitHub الخاص بك (إن لم يكن مرفوعاً مسبقاً).
2. افتح [vercel.com](https://vercel.com) → **Add New Project** → اختر هذا المستودع.
3. بشاشة الإعداد، أضف نفس المتغيرات الأربعة أعلاه تحت **Environment Variables**.
4. اضغط **Deploy**. خلال دقيقة تقريباً يصير عندك رابط ثابت مثل `alshulah-cars.vercel.app` (يمكن ربط دومين خاص لاحقاً من إعدادات Vercel).
5. أي تعديل تدفعه لاحقاً على فرع `main` (أو الفرع المرتبط بالنشر) يُنشر تلقائياً.

---

## 4) الاستخدام اليومي

- **الدخول**: كلمة مرور واحدة (`APP_PASSWORD`) — كافية لموظف واحد بمرحلة الإطلاق الأولى (زكريا). الجلسة تدوم 30 يوم على نفس الجهاز.
- **الصفحة الرئيسية** (`/`): سجل التشغيل اليومي — بحث، تسجيل عملية جديدة، ملخص مالي، تسوية بنكية، مستحقات، سجل اليوم.
- **الإعدادات** (`/admin`): تعديل أسعار الغسيل، الإضافات، الخدمات اليدوية، نسب عمولة البنك، وإضافة/إيقاف موظفين.

---

## 5) ملاحظات معمارية مهمة

- **لا يوجد Local Storage** — كل البيانات بقاعدة بيانات Postgres حقيقية على Supabase، تُقرأ من أي جهاز/متصفح.
- **الأمان**: مفتاح `service_role` لا يُستخدم إلا داخل Server Actions (كود يعمل على الخادم فقط) — لا يصل أبداً لمتصفح المستخدم. جداول قاعدة البيانات محمية بـ Row Level Security بدون أي policy عامة، فالوصول الوحيد الممكن هو عبر هذا المفتاح من كود الخادم.
- **الإعدادات النسخّية (Versioned Config)**: أي تعديل سعر/نسبة من `/admin` لا يُحدَّث بمكانه — بل يُغلَق السجل القديم (`is_current=false`) ويُضاف سجل جديد. كل عملية تحفظ **لقطة (snapshot)** من السعر والاسم والنسبة وقت تنفيذها بجدولي `transactions` و `transaction_services`، فتعديل لاحق لا يغيّر أي رقم بعمليات سابقة.
- **تفرّد السيارة**: المفتاح الحقيقي = (الإمارة + الرمز + الرقم)، لأن نفس الرمز/الرقم قد يتكرر بإمارات مختلفة. سيارات "بدون لوحة" (معارض) لا تُحفظ بهوية متكررة — فقط تُسجَّل بمرجع داخلي لكل زيارة، لكن صاحبها (برقم جواله) يتراكم تاريخه كعميل عادي.
- **مشاركة واتساب**: تفتح رابط `wa.me` جاهز بنص الكشف — تحتاج ضغطة إرسال يدوية (القيد الحالي لواجهة واتساب المجانية؛ الأتمتة الكاملة تحتاج WhatsApp Business API لاحقاً، خارج نطاق هذي المرحلة).

---

## 6) خارج النطاق حالياً (حسب مواصفات المشروع)

- قراءة آلية للوحات (OCR) — تحتاج API مدفوع متخصص لاحقاً.
- تسجيل دخول متعدد المستخدمين بصلاحيات مختلفة — البنية (`employees`) جاهزة للتوسّع لاحقاً، لكن الدخول حالياً بكلمة مرور واحدة مشتركة.
- تكامل WhatsApp Business API للأتمتة الكاملة.

---

## 7) هيكل المشروع

```
supabase/migrations/     ملفات SQL لإنشاء وتعبئة قاعدة البيانات
src/lib/actions/         منطق التطبيق (Server Actions) — بحث، تسجيل عمليات، إعدادات
src/lib/                 أنواع TypeScript، عميل Supabase، الجلسة/الدخول
src/app/                 الصفحات (الرئيسية، الدخول، الإعدادات)
src/components/          واجهة المستخدم (React) — مطابقة لتصميم الـ Prototype المرجعي
```
